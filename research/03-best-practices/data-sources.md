# 데이터 소스 조사: 서울 대중교통 실시간 API

## 서비스 범위

서울 중심으로 시작합니다. 지하철 실시간 열차 위치는 서울시 구간만 제공되므로,
버스도 동일하게 서울로 맞춰 데이터 정합성과 개발 속도를 확보합니다.

## 지하철

| API | 제공처 | 용도 |
|-----|--------|------|
| 서울시 지하철 실시간 열차 위치정보 | 서울 열린데이터광장 (TOPIS) | 탑승 열차 추적의 핵심 |
| 서울시 지하철 실시간 도착정보 | 서울 열린데이터광장 | 탑승 전 열차 선택 |
| 서울교통공사 역/노선 정보 | 서울 열린데이터광장 | 역 순서, 좌표 등 정적 데이터 |

주의: 서울시 이외 역구간은 미제공입니다. 또한 원천 수집 과정에서 시간 차가 발생하므로,
응답의 생성 시각(`recptnDt`)을 기준으로 신선도를 판단해야 합니다.

## 버스

| API | 제공처 | 용도 |
|-----|--------|------|
| 서울시 버스위치정보 | 서울 열린데이터광장 (TOPIS) | 탑승 차량 추적 |
| 서울시 버스도착정보 | 서울 열린데이터광장 | 탑승 전 버스 선택 |
| 서울시 정류소/노선 정보 | 서울 열린데이터광장 | 정류소 순번, 좌표 등 정적 데이터 |

버스 위치 응답에는 차량 ID와 현재 정류소 순번이 포함되어, 지하철과 동일한 추적 로직을 적용할 수 있습니다.

## 정적 데이터 사전 적재

역/정류소 목록과 노선별 정차 순서는 자주 바뀌지 않습니다.
매 요청마다 API를 호출하지 않고 빌드 시점 또는 최초 1회 적재하여 로컬에 보관합니다.
검색 응답 속도와 API 호출 한도 양쪽에서 이득이 큽니다.

## 공통 주의 사항

- API 키는 서버 사이드(Route Handler)에서만 사용합니다. 클라이언트 노출 시 유출됩니다
- 일일 호출 한도가 있으므로 실시간 응답도 수 초 단위 캐싱을 적용합니다
- 응답 필드명이 축약형이므로 `entities` 레이어에서 도메인 모델로 정규화합니다
- 지하철과 버스의 응답 스키마가 다르므로 어댑터를 각각 두고 공통 모델로 수렴시킵니다
