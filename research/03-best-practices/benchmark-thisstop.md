# 벤치마킹 분석: 이번정거장

## 대상

- 앱 이름: 이번정거장 (실시간 지하철 위치, 정차, 하차 알림)
- 웹: https://thisstop.co.kr/
- 플랫폼: iOS / Android

## 핵심 기능

| 기능 | 설명 |
|------|------|
| 실시간 열차 위치 | 탑승 전 열차가 어디까지 왔는지 확인 |
| 열차 선택 및 변경 | 대기 중 다음 열차로 손쉽게 변경 |
| 정거장 알림 | 역을 지날 때마다 현재 위치를 알림으로 통지 |
| 하차 알림 | 하차역 접근 시 하차 준비 알림 |
| 상황별 알림 | 탑승 중에는 진동, 하차 임박 시 음성 알림 |
| 가로형 노선도 | 열차 이동 경로를 실제 지하철 전광판과 동일하게 가로 표시 |

## 가장 중요한 구조적 발견

**이 앱은 기기 GPS를 사용하지 않습니다.**

지하철은 지하 구간에서 GPS 수신이 불가능합니다. 대신 사용자가 탑승한 열차를 지정하면,
서버가 실시간 열차 위치 API로 해당 열차를 추적하여 알림을 발송하는 구조입니다.

### 방식 비교

| 항목 | 기기 GPS 방식 | 차량 추적 방식 |
|------|---------------|----------------|
| 위치 출처 | `navigator.geolocation` | 공공 API의 차량 위치 |
| 지하 구간 | 동작 불가 | 정상 동작 |
| 백그라운드 | 브라우저 정책상 불가 | 서버가 추적하므로 가능 |
| 배터리 소모 | 큼 | 거의 없음 |
| 정확도 한계 | 신호 오차 | API 갱신 지연 |

차량 추적 방식은 웹 플랫폼의 백그라운드 위치 제약을 근본적으로 우회합니다.
따라서 본 프로젝트는 차량 추적 방식을 채택합니다.

## 버스로의 확장

버스 역시 차량 단위 실시간 위치(차량 ID, 현재 정류소 순번)가 공개되어 있어 동일 원리가 적용됩니다.
지하철과 버스를 하나의 추적 엔진으로 다루기 위해, 도메인 모델을 다음과 같이 추상화합니다.

- `Vehicle`: 추적 대상 차량 (열차 또는 버스)
- `Stop`: 정차 지점 (역 또는 정류소)
- `Route`: 운행 경로 (노선)

지하철과 버스의 차이는 `entities` 하위의 어댑터에서 흡수하며, 상위 추적/알림 로직은 공유합니다.

## 차별화 여지

- 이번정거장은 지하철 전용입니다. 버스 통합이 본 프로젝트의 주된 차별점입니다
- 환승 시나리오에서 지하철에서 버스로 이어지는 연속 알림은 기존 앱에 없는 영역입니다
